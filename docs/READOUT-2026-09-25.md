## In one paragraph
ProtoBase is a pocket notebook for **structured** notes: you type property/value pairs ("Name: La
Condesa", "Vibe: cozy"), press Save, and each record lands as a card in one of two databases. Data
stays in the browser; one button downloads the current database as a `.json` file for AI prompts or
future apps. It is live at https://vdm285.github.io/protobase/. The idea fits Victor's philosophy
well (no account, no backend, instant capture). The build does not yet: it loads ~826 KB (compressed)
of third-party code on every visit, cannot create or delete databases or records, has no import, and
is not really offline. The biggest risk is not ProtoBase's own data but **where it lives**: it runs
unpinned CDN scripts on the same web address as ListoLista.

---

## 1. What it does today (as built)
- Opens on the database "Restaurant Impressions" (a second one, "App Ideas Backlog", sits in the
  sidebar). These two are hard-coded; there is no way to add, rename or delete a database.
- **New record** panel: rows of *Property* + *Details* text boxes; "➕ Field" adds a row, 🗑️ removes
  one, "💾 Save" stores the record. After saving, the property names stay and the values clear, so
  the next record has the same shape. When you switch database, the form copies the property names
  of that database's **last** record ("dynamic schema").
- Records show as cards (property label above value). There is no edit, delete, search or sort.
- **JSON view** (💻 toggle) shows the current database as formatted JSON with a Copy button.
- **Export** downloads the current database as `<Name>_db.json`. There is no import.
- A demo record (a personal-sounding restaurant note) is pre-loaded for every new visitor
  and saved into their browser on first open; it cannot be deleted from the app.
- English UI, dark theme, sidebar on the left (on top on phones).

## 2. How it is built

| Piece | What | Where |
|---|---|---|
| Page | One `index.html`, React 18 app written in JSX inside `<script type="text/babel">` | `index.html:19-214` |
| React + ReactDOM | UMD builds from unpkg, version range `@18` (resolves to 18.3.1 today) | `index.html:9-10` |
| Babel | `@babel/standalone` from unpkg, **no version at all** (7.29.9 today); compiles the JSX in the visitor's browser on every load | `index.html:11` |
| Styling | Tailwind "Play CDN" `cdn.tailwindcss.com` (redirects to 3.4.17 today); builds CSS in the browser | `index.html:14` |
| Hosting | GitHub Pages from `main` (repo public, `has_pages: true`), address `vdm285.github.io/protobase` | GitHub API, 2026-09-25 |
| Build, tests, licence, service worker, manifest | none | — |

**Data model.** Two `localStorage` keys, both rewritten in full on every change (`index.html:48-54`):

```text
protobase_projects = [ {id:"1", name:"Restaurant Impressions"}, {id:"2", name:"App Ideas Backlog"} ]
protobase_data     = { "1": [ {id:"1790385208197", Name:"…", Vibe:"…", Food_Rating:"8/10", Notes:"…"} ],
                       "2": [ … ] }
```

Every value is a string; `id` is `Date.now()` as text (`index.html:83`). Property names are free text
and become JSON keys as typed (spaces allowed; blank becomes `Unnamed_Property`).

**Where data lives.** Only in the browser that typed it, under the origin `https://vdm285.github.io`.
That origin is shared with ai-council-workbench, compa-precio and listolista: one storage area, one
5 MiB `localStorage` quota for all four, and "clear site data" wipes all four
(ListoLista research `docs/research/2026-09-25-pwa-platform.md`; MDN, 2026-01-05).

**What a visitor downloads on each cold visit** (measured with `curl`, 2026-09-25):

| File | Raw | Gzip |
|---|---|---|
| ProtoBase's own `index.html` | 13.7 KB | 3.3 KB |
| react 18.3.1 | 10.8 KB | 4.3 KB |
| react-dom 18.3.1 | 131.8 KB | 42.9 KB |
| @babel/standalone 7.29.9 | 3,141 KB | 655.9 KB |
| Tailwind Play CDN 3.4.17 | 407 KB | 123.1 KB |
| **Total third-party** | **~3.7 MB** | **~826 KB** |

Both the Tailwind and the Babel files print a console warning that they are not meant for
production use (strings found inside the files).

## 3. What works
- Capturing a record with any properties, and seeing it immediately as a card. React escapes all
  text, so typing `<script>` or HTML into a field shows it as text (no injection hole found; checked
  every place record text is shown: `index.html:139, 191-192, 203`).
- Records survive reloads (same browser, same address).
- The "remember my fields" trick works when switching databases and after each save.
- JSON view, Copy, and Export of the current database.
- Layout adapts to phone width (sidebar stacks on top; view toggle becomes one icon).

## 4. Bugs and risks (most serious first)
Severity: 🔴 fix before more people use it · 🟠 fix in the next build · 🟡 polish.
Items are numbered 1-21 across the groups; section 6 refers to them as letter + number (e.g. B6).

### A. Security and privacy
1. 🔴 **Unpinned third-party code on a shared address** — `index.html:9-14`.
   The page runs whatever unpkg and cdn.tailwindcss.com serve today: Babel has no version pin, React
   floats within `@18`, there is no Subresource Integrity check. If either CDN is compromised, that
   code runs on `vdm285.github.io` and can read **every** app's storage there, including ListoLista's
   share-link secrets once checkpoint 1 is live (ListoLista `src/app.js:124, 192` keeps `secret` in
   its local index). This really happens: in June 2024 the polyfill.io CDN served malware to
   100,000+ sites (Sansec, 2024-06-25). SRI is the standard defence (MDN, 2026-04-14), but
   `cdn.tailwindcss.com` sends no CORS header (checked 2026-09-25), so SRI cannot be used for it;
   that file must be self-hosted or dropped.
   *Quick fix* (checkpoint 0, keeps the look): pin exact versions with these hashes (computed
   2026-09-25, stable over two downloads) and self-host the Tailwind file:
   ```html
   <script src="https://unpkg.com/react@18.3.1/umd/react.production.min.js" integrity="sha384-DGyLxAyjq0f9SPpVevD6IgztCFlnMF6oW/XQGmfe+IsZ8TqEiDrcHkMLKI6fiB/Z" crossorigin="anonymous"></script>
   <script src="https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js" integrity="sha384-gTGxhz21lVGYNMcdJOyq01Edg0jhn/c22nsx0kyqP0TxaV5WVdsSH1fSDUf5YJj1" crossorigin="anonymous"></script>
   <script src="https://unpkg.com/@babel/standalone@7.29.9/babel.min.js" integrity="sha384-oLbIC13I/8DNBviftYPfOFQS5DC2WUmwk0SyIPmnzu1Ui+vYyATSSBJiJ5ETa4o/" crossorigin="anonymous"></script>
   <script src="vendor/tailwind-play-3.4.17.js"></script>  <!-- copy of cdn.tailwindcss.com/3.4.17, sha384-igm5BeiBt36UU4gqwWS7imYmelpTsZlQ45FZf+XBn9MuJbn4nQr7yx1yFydocC/K -->
   ```
   *Real fix*: no third-party code at run time at all (step 3 below).
2. 🟠 **Shared storage with Victor's other apps** — same origin as above. Any of the four apps can
   read or overwrite `protobase_*` keys; they share one 5 MiB quota; clearing one clears all. Same
   issue is already in ListoLista's backlog ("move the app off the shared origin"). Decide together
   (Decision D5 in `ROADMAP.md`). Side note outside this repo: `compa-precio/index.html` loads
   `cdn.tailwindcss.com` and `unpkg.com/@phosphor-icons/web` unpinned too, so it carries the same
   exposure for the shared address.
3. 🟡 **Demo record for every visitor** — `index.html:27-31`. A personal-sounding note is the first
   thing a stranger sees, gets saved into their browser, and cannot be deleted. Replace with neutral
   Spanish examples (or start empty).

### B. Ways to lose data
4. 🔴 **"Offline capable" is only half true** — claim at `README.md:8`; no service worker or manifest.
   A tab that is already open keeps working without signal. But opening the page with no signal (or
   after iPhone Safari discards the tab) needs GitHub Pages plus four CDN files; the page's own
   cache lifetime is 10 min and the `react@18 → 18.3.1` redirects only 60 s (response headers,
   2026-09-25), so a cold open in a restaurant with no signal most likely shows a blank page
   *(check on phone)*.
5. 🔴 **No backup path back in** — `index.html:96-104`. Export exists, import does not, and there is
   no "export everything". Meanwhile Safari may delete script-written storage after seven days of
   browsing without a visit (MDN, 2026-01-05; WebKit, 2020-03-24), and the app never asks for
   persistent storage (`navigator.storage.persist()`).
6. 🟠 **Save quirks lose or garble data** — `index.html:79-94` (replayed in `jsc`):
   - Pressing Save twice stores an **empty record**: after a save the property names remain, and the
     filter at line 80 accepts rows whose name is filled even when the value is empty. Opening
     "Restaurant Impressions" and tapping Save once does the same. Empty records cannot be deleted.
   - Two rows with a blank property name: only the last value survives (both become
     `Unnamed_Property`, line 85).
   - Two rows with the same name: the last one silently wins (line 86).
   - A property called `id` replaces the record's id (lines 83, 86): it vanishes from the card
     (line 189) and two such records share a React key (line 187). A property called `__proto__` is
     silently dropped.
7. 🟠 **Two tabs overwrite each other** — `index.html:40-43, 52-54`. Each tab loads the data once and
   later writes the whole thing back; there is no `storage` event listener (MDN, 2026-08-21), so the
   last tab to save erases records added in the other.
8. 🟠 **One bad value blanks the app** — `index.html:36, 42` (`JSON.parse` without try/catch) and
   `49, 53` (`setItem` can throw when the shared 5 MiB quota is full). There is no error boundary, so
   React removes the whole page on such an error; the unsaved record is lost and the app stays blank
   until storage is cleared.

### C. Missing core features
9. 🟠 **Only two databases, forever** — `index.html:22-25`; `setProjects` is never called, and the
   sidebar (`118-131`) has no "new" button. For "an app that holds databases" this is the main gap.
10. 🟠 **No edit or delete of records** — `index.html:186-197`; typos and test records are permanent.
11. 🟡 Last database used is not remembered (`index.html:38` always opens database "1"), so
    zero-click start lands in the wrong place when you mostly use the other one.
12. 🟡 Everything is text: no number, date, rating, yes/no; no search or sort. Export needs cleaning
    before it is spreadsheet- or app-ready.

### D. Gaps against Victor's principles
13. 🟠 **Not "Notepad-instant"** — ~826 KB compressed / 3.7 MB of scripts parsed, and JSX compiled, on
    every visit for 14 KB of app (table in section 2). Tailwind's own docs say the Play CDN
    "is designed for development purposes only, and is not intended for production" (tailwindcss.com,
    fetched 2026-09-25); Babel's docs likewise advise precompiling instead of `@babel/standalone`
    in production (babeljs.io, fetched 2026-09-25).
14. 🟡 **Dead-end stack**: React 19 stopped shipping the UMD builds this page relies on
    (react.dev upgrade guide, 2024-04-25); npm "latest" is React 19.3.0 (2026-09-25).
15. 🟡 **English only**, `lang="en"` (`index.html:2`); Spanish-first not started.
16. 🟡 **No licence** while the repo is public (siblings compa-precio and ai-council-workbench use the
    Unlicense).

### E. Smaller bugs and polish
17. 🟡 State is changed in place in `handleFieldChange` (`index.html:72-73`); works today, fragile later.
18. 🟡 Full-height layout uses `h-screen` = 100vh (`index.html:109, 136`); on iPhone Safari the bottom
    can sit under the toolbar *(check on phone)*; `h-dvh` or the rebuild fixes it.
19. 🟡 Accessibility: text boxes have placeholders but no labels (`165-173`); emoji-only buttons
    (`147-149, 175`) have no `aria-label`.
20. 🟡 Copy gives no feedback and ignores failure (`index.html:106`); Export builds a `data:` link
    that is never attached to the page (`100-103`) and would be named `undefined_db.json` if the
    active database were missing (`99`). A Blob download is sturdier.
21. 🟡 Field rows use the row number as React key (`index.html:164`): after deleting a middle row the
    cursor can jump. The "remembered" fields come only from the last record (`59-67`).

## 5. How ProtoBase relates to ListoLista

| | ListoLista (`design/checkpoint-1`) | ProtoBase (`main`) |
|---|---|---|
| Job | One shared shopping list for two phones | Many small personal databases of structured notes; JSON out |
| Code | Plain JavaScript in `src/`, `tools/build.py` inlines it into one `index.html` (84 KB, everything included) | One `index.html`, React + Babel + Tailwind from CDNs (~826 KB compressed loaded) |
| Storage | `localStorage`, keys `listolista_*` | `localStorage`, keys `protobase_*` |
| Offline / install | Service worker + manifest + icons | None |
| Sync | End-to-end encrypted, Cloudflare relay, link `#k=` | None (export only) |
| Tests | 100+ headless tests with macOS `jsc` | None |
| Address | `vdm285.github.io/listolista` | `vdm285.github.io/protobase` (**same origin**) |

**Code ProtoBase can reuse from ListoLista** (copy now; both are single-file apps, so copying is cheap):
- `tools/build.py` (37 lines): edit small files in `src/`, ship one `index.html`.
- `src/sw.js` (28 lines) + `manifest*.webmanifest` + `icons/`: real offline start and "install as
  app", which makes the README claim true.
- The safe storage helper at the top of `src/app.js` (`store.get/set/del`, lines 17-19), the
  undo pattern, the iPhone install hint.
- `tests/run.sh` + `jsc` testing pattern for pure logic (a `src/db.js` module for ProtoBase).
- **Later, opt-in:** `src/merge.js` fits ProtoBase records almost as is if each record gains
  `timestamp` and `deleted` (it already merges "items by id, newest wins, deletions travel");
  `src/sync.js` + `relay/` store any JSON as an encrypted blob, but the relay caps a blob at 64 KB
  (`relay/src/index.js:18`, roughly 45 KB of JSON) and must list ProtoBase's address in
  `ALLOWED_ORIGINS`.

**Merge path, three options:**
1. **Sibling apps sharing a small kit** *(recommended)*: keep two apps with two jobs; ProtoBase adopts
   ListoLista's build, offline and storage pieces now, and the sync kit only if Victor wants shared
   databases. Extract a shared "kit" repo only when a third app needs the same parts.
2. ProtoBase as the engine, ListoLista as a "template" on top: elegant in theory, but it would slow
   down ListoLista, which is one phone test away from going live. Not now.
3. One merged app: breaks the Notepad benchmark for both. No.

A natural link: ProtoBase can be the **data bench for future apps**. ListoLista's aisle dictionary,
store aisle orders, or compa-precio prices are exactly "databases for future apps" that someone
could collect by hand in ProtoBase and export. Apps should exchange data through files or the
encrypted link, **not** by reading each other's storage on the shared address (that is the hole in
A1/A2).

   the last three things you actually wanted to capture with it?

   conflicts with isolating ListoLista.)

   tested the same way)? Or do you want React for learning or portfolio reasons?

   makes sense? Keep the name ProtoBase?
8. **Backups and address:** is a downloaded JSON file a good enough backup, or do you want CSV /
